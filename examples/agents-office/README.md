# Agents Office

Панель управления агентами для Telegram-магазина витаминов. Это работающая
программа, а не макет: оркестратор принимает задачу, выбирает агента, запускает
его на модели, показывает статусы в реальном времени и кладёт результат к вам на
подтверждение.

![Панель](./panel-preview.png)

## Что внутри

| Часть | Файл | Что делает |
|---|---|---|
| Реестр агентов | `src/registry.js` | Читает markdown-файлы с агентами: 6 своих из `agents/` + 9 из каталога репозитория |
| Хранилище | `src/store.js` | Журнал событий в JSONL и снимок задач. Без native-зависимостей, переживает перезапуск |
| Оркестратор | `src/orchestrator.js` | Очередь, выбор агента, запуск, статусы, подтверждение и отклонение |
| Модель | `src/llm.js` | Вызов Claude через официальный SDK. Без ключа — демо-режим |
| Сервер | `src/server.js` | REST + поток событий SSE + отдача панели |
| Сцена офиса | `public/scene.js` | Изометрические острова-отделы, рабочие места с мониторами, камера с подлётом |
| Панель | `public/` | Экран сотрудника, очередь на подтверждение, статус задач |

Зависимость ровно одна — `@anthropic-ai/sdk`. Всё остальное на стандартной библиотеке Node.

## Как выглядит работа

Офис нарисован изометрией: каждый отдел — остров, на нём рабочие места со
столом, креслом и монитором. Клик по острову подводит камеру к отделу, клик по
сотруднику — вплотную к его рабочему месту.

Текст от модели идёт **потоком**: `llm.js` подписывается на `stream.on('text')`,
оркестратор с частотой не выше четырёх раз в секунду отдаёт накопленное в
событие `task.progress`, панель показывает его на экране сотрудника. То есть
видно, что агент пишет прямо сейчас, а не только готовый результат.

## Пакет знаний магазина

Агенты берут факты не из головы, а из папки `знания/` — выгрузки из рабочей базы
магазина, которую собирает скрипт `python3 знания/обновить.py`.

| файл | что внутри |
|---|---|
| `бизнес.md` | кто мы, доставка, оплата, каналы, чего пока нет |
| `тон.md` | как магазин разговаривает, с примерами |
| `товары.csv` | весь активный каталог: цена, остаток, описание |
| `срез.md` | бренды, категории, что заканчивается |
| `темы.md` | готовые разборы тем здоровья со связкой «проблема → товары» |
| `правила.md` | что нельзя писать про добавки |
| `конкуренты.md` | кто вокруг |

Приложение собирает из этого контекст под каждого агента: всем — бизнес, тон,
правила, срез и каталог; тем, кто пишет тексты, добавляются разборы тем.
Получается 31–54 КБ на вызов, повторные вызовы дешевеют за счёт кэша промпта.

**Папка не коммитится.** В ней реальные цены, наценка, телефон и адрес, а
репозиторий публичный — поэтому `знания/` стоит в `.gitignore`. Кладите выгрузку
на диск рядом с приложением, оно подхватит её при старте. После смены цен или
остатков выполните `обновить.py` и нажмите «Перечитать знания» в окне «Мозг» —
или перезапустите сервер.

Если папки нет, приложение откатывается на простой `BRAIN.md` и продолжает
работать — так его можно применить к любому другому магазину.

## Запуск за две минуты (демо-режим)

```bash
cd examples/agents-office
npm install
npm start
```

Откройте `http://127.0.0.1:8787`. Без ключа агенты отвечают заглушками — это
нужно, чтобы посмотреть, как задача проходит по статусам, не тратя деньги.
В шапке будет честно написано «демо-режим».

## Боевой режим

```bash
cp .env.example .env
# впишите ANTHROPIC_API_KEY
set -a && source .env && set +a
npm start
```

Модель по умолчанию — `claude-opus-5`, меняется через `AO_MODEL`.

## Что мне нужно от вас, чтобы это заработало полноценно

По возрастанию сложности.

**1. Ключ Anthropic — обязательно, без него только заглушки.**
Берётся на console.anthropic.com → API Keys. Кладётся в `.env`, в репозиторий не
попадает. Это единственное, что нужно, чтобы агенты заработали по-настоящему.

**2. Актуальный пакет знаний — обязательно.**
Папка `знания/` рядом с приложением. Без неё агенты будут честно отвечать
«не хватает данных» — и это правильно, иначе они начнут выдумывать состав и цены.

**3. Доступ к серверу — когда будем разворачивать.**
Нужны: адрес, SSH-доступ, версия ОС, стоит ли nginx, есть ли свободный домен или
поддомен. Ключи не присылайте в чат — их вводите вы сами на своей машине.

**4. Данные магазина — для следующего шага.**
Чтобы агенты видели реальные заказы, нужен доступ на чтение к базе бота: тип базы
(SQLite, Postgres), где лежит, какие таблицы. **Не токен бота** — читать надо
сбоку от базы. Второй потребитель Bot API конфликтует с вебхуком и может
остановить приём заказов на боевом магазине.

**5. Репозиторий бота — когда будем связывать напрямую.**
Если бот лежит на GitHub, дайте ссылку, и я подключу его как источник данных.

## Разворачивание на сервере

```bash
git clone <ваш-репозиторий> /opt/agents-office
cd /opt/agents-office/examples/agents-office
npm ci --omit=dev
```

`/etc/systemd/system/agents-office.service`:

```ini
[Unit]
Description=Agents Office
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/agents-office/examples/agents-office
EnvironmentFile=/opt/agents-office/examples/agents-office/.env
ExecStart=/usr/bin/node src/server.js
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now agents-office
sudo journalctl -u agents-office -f
```

Nginx поверх:

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;          # обязательно: иначе поток событий встанет
    proxy_read_timeout 3600s;
}
```

### Безопасность

Панель запускает платные вызовы модели и показывает данные магазина.

- Задайте `AO_TOKEN` перед тем, как открывать её наружу. Вход тогда по
  `https://ваш-домен/?token=...`.
- Держите `AO_HOST=127.0.0.1` и пускайте трафик только через nginx с HTTPS.
- `.env` и папка `data/` не коммитятся — они в `.gitignore`.

## Как добавить агента

1. Положите markdown-файл с frontmatter (`name`, `description`, `emoji`, `color`)
   в `agents/` или возьмите готовый из каталога репозитория.
2. Добавьте строку в `ROSTER` в `src/registry.js` — путь, блок, волну.
3. Перезапустите сервер.

## Чего пока нет

Честный список, чтобы не было сюрпризов:

- **Нет связи с ботом и магазином.** Задачи ставите вы руками через панель.
  Подключение к базе заказов — следующий шаг, см. пункт 4 выше.
- **Нет расписания.** Задачи не запускаются сами по времени.
- **Нет отправки покупателю.** Агент готовит текст, вы копируете и отправляете.
  Это сделано намеренно: автоотправка от вашего имени — слишком дорогая ошибка.
- **Нет пользователей и ролей.** Один владелец, один токен.

Всё это добавляется поверх текущей архитектуры, когда станет ясно, какие задачи
вы реально гоняете каждую неделю.
