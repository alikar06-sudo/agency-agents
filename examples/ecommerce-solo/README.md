# Соло-магазин: три агента, мозг и расписание

Рабочая сборка для одного человека, который продаёт товары. Не 35 агентов и не
схема офиса — три рутины, которые реально повторяются каждую неделю, плюс общий
контекст, чтобы не объяснять всё заново в каждом чате.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `BRAIN.md` | Шаблон контекста: товары, тон, ЧаВо, правила, цифры. Заполняете вы |
| `my-agents.txt` | Список из трёх агентов для установки одной командой |
| `README.md` | Этот файл: порядок внедрения и первые задачи |
| `ORG.md` | Полная карта на 30 ролей для Telegram-магазина: кто чем занимается, что уже есть в каталоге, что надо написать |

## Порядок — три недели

### Неделя 1. Заполнить BRAIN.md

Сначала это, до установки агентов. Без контекста агент выдаёт общие советы из
интернета, вы разочаровываетесь и бросаете — так обычно и заканчивается.

Один вечер. Не обязательно идеально: раздел «Частые вопросы» можно собрать,
просто пролистав переписку с покупателями за последний месяц.

### Неделя 2. Поставить агентов и прогнать на реальных задачах

```bash
# посмотреть, что встанет, ничего не записывая
./scripts/install.sh --tool claude-code --agents-file examples/ecommerce-solo/my-agents.txt --dry-run

# установить
./scripts/install.sh --tool claude-code --agents-file examples/ecommerce-solo/my-agents.txt
```

Строка `[OK] Claude Code: 3 agents` в конце — это сколько агентов реально
нашлось. Если там меньше трёх, значит слуг в списке не совпал с именем агента:
опечатка молча пропускается.

Для другого инструмента поменяйте `--tool`: `cursor`, `codex`, `gemini-cli`,
`copilot` и так далее — список в `./scripts/install.sh --help`.

Первые задачи — по одной на агента, на **реальных** данных, не на выдуманных:

**Email Marketing Strategist**
```
Прочитай BRAIN.md. Напиши цепочку из трёх писем для брошенной корзины:
через 1 час, через 24 часа, через 3 дня. Без давления и фальшивой срочности,
тоном из раздела 3. Скидку не предлагай раньше третьего письма.
```

**Content Creator**
```
Прочитай BRAIN.md. Составь контент-план на 2 недели для <ваша площадка>:
8 постов. Под каждым — тема, зачем он нужен и первая строка.
Опирайся на возражения из раздела 4, а не на общие советы.
```

**Support Responder**
```
Прочитай BRAIN.md. Вот реальное сообщение покупателя: <вставить>.
Напиши три варианта ответа: короткий, подробный и для случая,
когда клиент раздражён. Соблюдай правила из разделов 6 и 8.
```

Если ответ вышел общим — почти всегда дело не в агенте, а в пустом разделе
BRAIN.md. Дозаполните и повторите.

### Неделя 3. Расписание и правило подтверждения

Выберите **одну** задачу и поставьте её на конкретный день недели. Например:
понедельник — контент-план на неделю. Одна регулярная задача, которая правда
выполняется, стоит больше пяти, про которые вы забыли.

И жёсткое правило, то самое `WAITING APPROVAL` со скриншота:

> Ничего не уходит покупателю, в рассылку или в рекламу без вашего прочтения.

Агент готовит — вы проверяете и отправляете. Для соло это не перестраховка:
одно письмо не тем тоном по всей базе откатывает работу месяцев.

## Что дальше

Через 2–3 недели, если три рутины прижились, раскомментируйте в `my-agents.txt`
**одного** агента из блока «второй заход» и повторите установку. По одному, а не
пачкой: каждый новый агент — это ещё один выход, который надо проверять.

## Чего здесь нет

Честно, чтобы не было ожиданий из ролика:

- **Агенты не подключены к магазину, почте и рекламному кабинету.** Это промпты,
  которые работают в вашем чат-инструменте. Данные вы приносите руками
  (скопировать письмо, выгрузить таблицу). Подключения — отдельная работа.
- **Никто ничего не делает сам, пока вас нет.** «Runs headless» со скриншота
  требует отдельной системы с очередью задач и доступами.
- **Нет дашборда.** Статусы, счётчики и лента задач — это UI поверх рантайма,
  которого в этом репозитории нет вообще: тут 316 markdown-файлов и скрипты
  установки, ни строчки кода приложения.

Всё это делается — но только после того, как станет понятно, какие три рутины
действительно повторяются. Автоматизировать имеет смысл то, что уже работает.

## Память между сессиями

Если надоест каждый раз просить «прочитай BRAIN.md», в репозитории есть
`integrations/mcp-memory/` — как подключить агентам постоянную память через MCP,
чтобы контекст подтягивался сам. Это тот же «мозг», только автоматический.
Не раньше, чем BRAIN.md будет заполнен и обкатан.
